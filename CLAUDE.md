# CLAUDE.md — Project Development & Verification Protocol

## TRI-AGENT WORKFLOW PROTOCOL (v4.1 — RE-VERIFICATION ENABLED)

This document outlines the collaborative workflow between three AI agents and the gatekeeper system for ensuring code quality and automated verification.

### 1. AI ROLES & AWARENESS

**Master Architect (Gemini)**
- วางแผนสถาปัตยกรรมระดับสูง (High-level architecture planning)
- กำหนดเป้าหมาย (Set objectives)
- ออกคำสั่งแบบ Structured Task (Issue structured task commands)

**Execution Engine (Claude Code / OpenCode)**
- เขียนโค้ดตามสั่ง (Write code per specifications)
- Auto-Fix บั๊ก (Auto-fix bugs detected by tests)
- รับผิดชอบการวิ่ง Loop ตรวจสอบจนกว่าจะผ่านจริง (Manage verification loop until all tests pass)

**Gatekeeper Auditor (LocalCore CLI)**
- ตรวจสอบโค้ดแบบ Read-Only (Read-only code verification)
- พ่นค่า Exit Code (Emit exit codes: 0=PASS, 101/102/103=FAIL)
- ตรวจสอบความสมบูรณ์ของโครงการ (Verify project completeness)

---

### 2. GATEKEEPER EXECUTION RULE

**ALWAYS use global Windows PATH and Delayed Expansion (/v:on) to capture accurate exit codes:**

```batch
cmd /v:on /c "localcore --verify --model "<MODEL_NAME>" & echo EXIT_CODE:!ERRORLEVEL!"
```

**Note:** Execution Engine must replace `<MODEL_NAME>` with the active local LLM:
- Default: `Qwen-2.5-Coder-14B`
- Alternative: `claude-opus`, `claude-sonnet` (if available)

---

### 3. AUTOMATED VERIFICATION & RE-VERIFICATION LOOP (CRITICAL)

After executing the Gatekeeper command, the Execution Engine MUST strictly follow this workflow:

#### [A] INITIAL AUDIT CHECK

**If EXIT_CODE: 0 (PASS)**
- ✅ Proceed immediately to Version Bump
- ✅ Update Audit Trail (HISTORY.md)
- ✅ Build Release Artifacts
- ✅ Push to GitHub

**If EXIT_CODE != 0 (FAIL: 101, 102, 103)**
- ❌ Enter the Auto-Fix & Re-Verification Loop (see below)
- ❌ DO NOT proceed with version bump or release

#### [B] AUTO-FIX & RE-VERIFICATION LOOP (DO NOT STOP)

This loop continues until EXIT_CODE: 0 is achieved:

**Step A (Analyze)**
- Read the error trace/logs generated by LocalCore
- Identify root cause of failure
- Document the issue for transparency

**Step B (Fix)**
- Perform targeted code modifications to resolve root cause
- Commit changes with descriptive message
- DO NOT introduce new issues while fixing

**Step C (Re-Verify)**
- MUST re-run the Gatekeeper Execution Rule immediately
- Capture new EXIT_CODE

**Step D (Evaluate Re-Audit)**
- If Re-Audit returns **EXIT_CODE: 0**
 - ✅ Fix confirmed! Proceed to Version Bump & Release
 - ✅ Document the fix in HISTORY.md
 - ✅ Update CHANGELOG.md

- If Re-Audit STILL returns **EXIT_CODE != 0**
 - ❌ Return to Step A and repeat the loop
 - ❌ Maximum retries: 5 (then escalate/investigate deeper)

#### [C] STRICT EXIT CONDITION

- The task is **NEVER considered complete while in a FAIL state**
- A final Re-Verification audit yielding **EXIT_CODE: 0** is **MANDATORY** before declaring completion
- All loop iterations must be documented in HISTORY.md with timestamps

---

### 4. PROJECT-SPECIFIC GATEKEEPER COMMANDS

**For doc2md v0.2.1:**

```bash
# Full verification with coverage
pytest tests/ --cov=doc2md --cov-fail-under=90 -v

# Via LocalCore (recommended)
cmd /v:on /c "localcore --verify "pytest tests/ --cov=doc2md --cov-fail-under=90 -v" --model "Qwen-2.5-Coder-14B" & echo EXIT_CODE:!ERRORLEVEL!"

# Quick sanity check
pytest tests/ -x --timeout=10

# Coverage report only
coverage run -m pytest tests/ && coverage report --include=doc2md/*
```

**Expected Metrics:**
- Test Count: ≥252
- Coverage: ≥90%
- Exit Code: 0
- Build Time: <30 seconds

### 7. COMMUNICATION PROTOCOL

**Execution Engine to Master Architect:**
- Report EXIT_CODE immediately after gatekeeper run
- Provide clear root-cause analysis for any FAIL
- Request architecture guidance if fixes are unclear

**Master Architect to Execution Engine:**
- Confirm proceeding with release only on EXIT_CODE: 0
- Escalate if loop exceeds 3 iterations
- Approve or reject architecture changes to fix failures

**All to Gatekeeper:**
- Respect exit codes as the source of truth
- No manual overrides without written justification
- All verification runs logged in HISTORY.md

### 9. ESCALATION & FAILURE SCENARIOS

**Scenario: EXIT_CODE 101 (Missing dependencies)**
1. Analyze: Check which module/package is missing
2. Fix: Update `pyproject.toml` or install via pip
3. Re-Verify: Confirm dependency resolution

**Scenario: EXIT_CODE 102 (Test timeout)**
1. Analyze: Identify which test timed out
2. Fix: Increase timeout in `conftest.py` or optimize test
3. Re-Verify: Confirm test completes within time limit

**Scenario: EXIT_CODE 103 (Coverage below 90%)**
1. Analyze: Identify untested code paths
2. Fix: Add tests in `tests/test_*.py`
3. Re-Verify: Confirm coverage ≥90%

**Escalation Trigger:** If loop exceeds 5 iterations → Contact Master Architect for guidance
